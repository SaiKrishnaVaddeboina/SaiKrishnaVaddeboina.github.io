The Problem

Real-estate transactions are slow, opaque, and expensive.

Title transfers route through escrow, county recorders, and notaries — a process measured in weeks, with intermediary fees stacking at every step. Buyers can't verify ownership history without paying a title company; sellers can't accept atomic settlement; pricing data lives in centralized MLS databases. The result is a market that runs on trust in institutions rather than verifiable record.

This project asks: what does property transfer look like when the source of truth is a blockchain instead of a county clerk?

The Build

Smart contracts on the back, Vue.js on the front, Docker around the whole thing.

01 · Smart Contracts

Solidity + OpenZeppelin

Property contracts inherit OpenZeppelin's audited Ownable, AccessControl, and ReentrancyGuard. Truffle handles compilation, migration, and test deployment.

02 · Multi-Sig Governance

Threshold-based ownership transfer

Property transfers above a configurable value require N-of-M signatures. Implements a custom multi-sig wallet pattern — proposed transactions sit in a pending state until quorum approves.

03 · Role-Based Access

Owner · Agent · Buyer

Three on-chain roles with distinct permissions: only owners can list, only verified agents can broker, only KYC'd buyers can submit offers. Role grants emit events that the front-end indexes.

04 · Oracle Price Feeds

Chainlink integration

Listings denominated in USD but settled in ETH. Chainlink price oracles convert at execution time, eliminating the front-running risk of stale price quotes.

05 · Web Stack

Vue.js + Express + MongoDB

Vue.js front-end talks to contracts via Web3.js. Express API caches event-log data into MongoDB so the UI loads property history without scanning the chain on every page hit.

06 · Containerization

One-command Docker deploy

Docker Compose spins up Ganache (local chain), Mongo, Express API, Vue dev server, and a contract migration step in a single docker-compose up — reviewer can clone and run end-to-end in under two minutes.

Architecture Highlights

Three design choices that mattered.

OpenZeppelin everywhere

Wrote zero security primitives from scratch. Inherited AccessControl, Ownable, ReentrancyGuard, and Pausable from OpenZeppelin's audited library — the security surface area becomes their problem, not mine.

Events as the API

Every state change emits an indexed event. The Express layer subscribes to event logs and projects them into MongoDB views — meaning the database is always rebuildable from on-chain truth, never the other way around.

Oracle for price, not for data

Chainlink only feeds price conversion, not property data. Property facts live on-chain. This keeps the trust surface narrow: oracles handle one thing they're good at, the contract handles authoritative state.

Docker as documentation

The docker-compose.yml is the deployment spec. Anyone evaluating the project can run it without reading setup docs — which is exactly how a real engineering team should hand off code.

What I Learned

Smart contracts are unforgiving — and that's the point.

Working in Solidity changed how I think about state. There's no "I'll fix it in a hot patch." Once a contract is deployed, every line of logic is visible, every gas cost is paid, every bug is permanent. That constraint forces a discipline you don't get from web frameworks — defensive programming becomes the default, not a code-review nice-to-have.

It also clarified where blockchain belongs and where it doesn't. On-chain works for ownership truth and price-agnostic settlement. Off-chain works for everything else — UI, search, indexing, marketing copy. The interesting engineering happens at the boundary.
